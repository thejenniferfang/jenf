ui-agent

July 2026, still in progress

ui-agent is a small panel you mount in a React app during development. It lets you edit design tokens live in the browser, then writes the change back to your stylesheet. It also looks at the page for the things that are almost right, which is the category the eye reads as sloppy without being able to name, and turns them into a brief a coding agent can act on.

Most token editors are runtime knobs. You tweak a value, you like it, and then you go find the file and type it in again by hand. This one closes that loop. It also keeps the values you rejected, which turn out to be the more useful half of the record.

The code is on GitHub. It is published as @jenfang/ui-agent.

Tokens

Each group of tokens becomes a section of sliders. Units come from the token values themselves, so a radius group slides in pixels and a motion group slides in milliseconds. The groups are read from a DTCG-style manifest where every token records the custom property that controls it.

{
  "radius": {
    "soft": {
      "$type": "dimension",
      "$value": "4px",
      "$variable": "--radius-soft",
      "$utilities": ["rounded-soft"]
    }
  }
}

The variable is the required part. It is what makes an edit unambiguous: the panel sets that property at runtime, and the writer changes that exact declaration in your stylesheet. The utilities list is optional and only displayed, so you can see the blast radius of a change before you make it.

The decision log

Every apply and every reset appends one line to a log. A reverted entry never touches the stylesheet. It exists because the value someone tried and threw away, plus the reason, says more about a design system than the value that happened to stick. Read a few weeks of this and the house style is written down whether anyone meant to write it or not.

{"action":"applied","edits":[{"token":"radius.soft","from":"4px","to":"8px"}],
 "note":"4px reads too soft next to the 2px data surfaces"}
{"action":"reverted","edits":[{"token":"radius.soft","from":"8px","to":"16px"}],
 "note":"way too round, looks like a consumer app not a data tool"}

What it refuses to do

An HTTP endpoint that edits source deserves guards. A variable name that is not a plain custom property is rejected. A value that is not a bare CSS length is rejected. And a declaration whose value is itself a var(...) is refused, because in a Tailwind theme block those aliases are what hold a scale together. Overwriting one with a literal would silently flatten the scale, so the writer only ever touches declarations that already hold a literal value.

Inspect

Click any element to see what its radius resolves to and whether a token owns it, or whether it is hardcoded. It also checks the concentric radius rule on the element's parent: inner radius should equal outer radius minus padding, so the padding reads as optically even around the corner.

Align

Click a container to check its children. Guide lines are drawn over the page, faint on the edge most items share and hard on the strays.

Five checks run. Near-miss edges, where items nearly agree. Broken rhythm, where gaps run 12, 12, 13, 12. Off-grid values. Padding drift between siblings. And padding asymmetry, where 16px on top sits against 14px on the bottom. A header padded 24 top and 8 bottom is a shape someone chose; 16 and 14 is a typo.

Switching to the whole page checks alignment between components rather than inside one container. It finds spines, edges that several elements share exactly, and reports anything sitting near a spine without landing on it. This is deliberately not a comparison of every element to every other element. Across unrelated components almost any pair lands within a few pixels of something, so that approach produces noise instead of findings. Anchoring to a line the page already committed to is what makes a cross-component result mean anything.

Two things look like misses and are not. A card with a one-pixel border holds its rows one pixel inside its own edge, and moving them would push them onto the border. And two real lines a pixel apart are two lines, not one line and six strays. Both are counted and set aside, and the counts are always shown. A check that quietly discards most of what it found is indistinguishable from one that found nothing.

When no value holds a majority, it says so rather than picking one. Two items two pixels apart are misaligned, but nothing says which one moved. Naming a target there would be a guess dressed up as a finding.

Nudge

Audit is the tool telling you what is wrong, and that is always a guess about intent. Nudge is the other direction: you tell the tool. Every line the page commits to is drawn, including the ones nothing misses. Click an element to pick it up, drag it or use the arrow keys, and an edge within six pixels of a line sticks to it. Nothing about the page changes. The move is a transform, so layout, scroll height and every sibling stay exactly where they were.

Copy feedback turns the moves into a brief, with both positions given rather than a delta, so the agent can check the claim against the layout instead of trusting a number.

Type

Censuses every rendered text size and weight, then flags what is off your scale or spaced too finely to read as steps. A page using 10, 11, 12, 13, 14 and 15 has one problem, a ramp finer than the eye reads as steps, not five separate ones.

House rules can be switched on. One of them flags monospace text that is also uppercased. Mono already signals machine; uppercasing it costs legibility without adding meaning.

Install

npm install @jenfang/ui-agent

React 18 or 19 is a peer dependency. Mount it once, gated to development, and pass the tokens you want to expose.

import { groupFromManifest, UiAgent } from "@jenfang/ui-agent"
import manifest from "@/design-tokens.generated.json"

const groups = [
  groupFromManifest(manifest, "radius", { min: 0, max: 24, step: 1 }),
  groupFromManifest(manifest, "motion", { min: 0, max: 600, step: 10 }),
]

export function UiAgentProvider() {
  if (process.env.NODE_ENV !== "development") return null
  return (
    <UiAgent
      groups={groups}
      endpoint="/api/ui-agent"
      source="app/globals.css"
    />
  )
}

The endpoint is yours to mount, so the package does not depend on your framework. It writes to tracked source files, so gate it to development.

This is a v1 and it is still moving. The full write-up, including the parts about how the panel is drawn and why the orb stays dark in both themes, is in the README.
